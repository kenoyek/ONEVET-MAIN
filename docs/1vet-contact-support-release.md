# Contact and support reliability — 15 November 2026

Contact now requires the existing Edge Function's explicit `{success:true}` response before clearing the form or claiming receipt. Repeated submissions are locked while pending and all fields are disabled. An unconfirmed result leaves input intact and displays inline retry/email guidance; success remains visible and receives keyboard focus. This protects against duplicate pending clicks, not duplicate records after an ambiguous network failure and later retry—the backend has no contact idempotency contract.

The support page now routes visitors to appointment requests, care discovery, urgent-care guidance and provider registration. It removes unsupported promises of instant nationwide vet access, automatic membership benefits and guaranteed 24-hour replies. The form has associated field errors, schema validation and input bounds, plus a privacy link. A city-level map was replaced with provider-support guidance rather than presenting it as an exact clinic address. The existing phone +2347052398371 and support email remain.

No support message was sent to the live service and no Edge Function/database deployment is required. Existing backend acknowledgement format was inspected in supabase/functions/contact-form/index.ts. Frontend tests verify one pending send, explicit acknowledgement, retained input/retry, invalid input and real contact destinations. Application/API typechecks, lint and production build pass. Local Chromium intercepts all backend responses and verifies failure/retry, success focus and widths 1440, 390 and 320 in light/dark themes without production writes. This does not verify live support delivery or response times.
