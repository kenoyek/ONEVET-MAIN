# Calendar preparation feedback — 19 November 2026

Calendar preparation now has a synchronous in-flight guard scoped to the signed-in account and appointment, preventing rapid clicks from preparing duplicate files. A preparation for a new scope remains independent; completion of an older request cannot unlock or update that newer operation. Existing unmount and account/appointment response guards remain in effect.

Successful preparation shows the freshly rechecked appointment time in WAT and explains that the file can be imported into a calendar app. This acknowledges file preparation, not proof that the browser saved it or a calendar app imported it. A failed preparation offers an explicit Retry calendar download action, which repeats the authorized appointment check. Feedback from a previous scope is hidden.

The existing calendar generation rules are unchanged: only eligible current confirmed participant appointments can be copied; stable event identity, UTC instants, version sequence and private classification remain. Animal, service, clinical, phone and address details remain omitted. Copies do not update automatically and previous copies must be reviewed after cancellation or rescheduling. No invitations, email, alarms, appointment mutations or payment changes are introduced.

All 622 tests across 133 files pass. Validation covers duplicate clicks, freshly checked metadata, explicit retry, overlapping scope changes, late responses and receipt isolation, alongside existing calendar-format and privacy tests. Local Chromium confirms failed preparation and explicit retry, one actual ICS from rapid clicks, fresh time/version, omitted private fields and a visible receipt at widths 1440, 390 and 320 without runtime exceptions. Browser checks use synthetic appointments and inspect a locally downloaded ICS file, not production calendar data. Type checking and production build pass; lint reports zero errors and nine existing warnings. No migration, backend deployment or cloud environment publication is included.
