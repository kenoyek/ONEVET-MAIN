# Appointment conversation recovery — 18 November 2026

If a conversation access check fails after a client has typed a draft, the client can now copy that draft from a read-only field while retrying access. Server messages remain hidden until access is verified again. A recovered access check restores the draft to the composer. Read-only conversations use the same retained-draft presentation. Drafts stay in component memory, keyed by account and appointment; this change adds no browser persistence or cross-account recovery.

Message submission now uses a synchronous in-flight lock in addition to disabled controls. Programmatic submission is blocked when access or message loading has failed. The existing server retry nonce is retained after ambiguous send failures. A confirmed send clears the draft and remains reported as saved even if refreshing the conversation view fails; the client is told to refresh rather than resend.

Read-status acknowledgement has its own in-flight guard and error guidance. A failed acknowledgement no longer asks clients to retry a message. Only the visible page’s latest ordinal is acknowledged. Existing server permissions, read-only status, rate limits, participant scoping, chronological pagination and immutable plain-text messages remain unchanged.
