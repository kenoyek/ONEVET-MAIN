# Pet onboarding and booking return — 11 November 2026

The new-animal path from an appointment request now opens pet registration with an internal booking return route. Saving returns to the selected service/date/time with the new pet selected. Availability and ownership are still checked by the booking form and backend. Direct pet registration retains its normal profile destination, and Back has a predictable internal destination.

Pet creation is scoped to the current active owner profile and uses a stable UUID per mounted form with a synchronous save lock. A retry after a lost response can recover the first saved record by that UUID and owner ID instead of creating another animal or overwriting the saved record. Forms lock while saving or uploading. Errors preserve entries, and an old form cannot navigate after unmounting/account change.

Pet photos previously used profile IDs as storage folders although storage requires auth user IDs. The uploader now writes unique, immutable files under the signed-in user ID, with browser image validation/re-encoding/resizing and a 5 MB input limit. It waits for any profile-reference update to finish and retains the old photo when upload/attachment fails. Removing/replacing a photo updates the reference without deleting media first. Pet deletion no longer removes media before confirming the record deletion; retained media requires trusted orphan cleanup. Existing public photo/private evidence bucket boundaries are unchanged.

Validation: 368 tests in 96 files passed; typecheck and production build passed. Lint has zero errors and nine existing warnings. New tests cover auth-folder ownership, duplicate uploads, old-image preservation, removal failures, duplicate pet saves, stable retry IDs, owned-record recovery and restricted return routes. Chromium verified no-animal booking → pet creation → processed photo upload → booking return with the new pet selected, at widths 1440/390/320 without overflow or runtime exceptions. Responses were synthetic fixtures; no actual production pets or photos were created. Session artifacts are under `/workspace/artifacts/1vet/pet-onboarding`.
